# Лот

Сайт оплаты и выдачи ключей VPN из панели 3x-ui. Вход только по почте. После уведомления Робокассы сервер создаёт нового клиента или продлевает выбранный ключ.

В папке проекта:

- `install.sh` ставит Node.js, зависимости и службу, затем создаёт `.env`. Повторный запуск с `start` поднимает сайт.
- `server.mjs` сам сайт: страницы, вход по введённой почте, Робокасса, панель 3x-ui и база. При старте читает соседний `.env`.
- `package.json` список зависимостей и команды `npm run setup`, `npm start`.
- `package-lock.json` точные версии этих зависимостей.
- `.gitignore` не даёт закоммитить `.env` и `node_modules`.
- `cursor-app.json` просит у площадки Cursor свою Postgres. На своём сервере не используется.
- `.env` появляется после `./install.sh` и хранит пароли рядом с кодом. В git его нет.

На сервере, в этой папке:

```bash
./install.sh
nano .env
./install.sh start
```

Без `DATABASE_URL` пользователи и ключи живут в памяти процесса и пропадают при перезапуске. Настоящие платежи включаются, когда в `.env` заданы Робокасса и панель вместе с `XUI_INBOUND_ID`, и нет строки `ROBOKASSA_TEST=1`. Эта строка создаёт тестовый счёт: деньги не списываются. Почта для входа никуда не отправляется. `SMTP_*` нужен только если после оплаты надо ещё и прислать ключ письмом.

Цены меняются на странице `/admin`. В `ADMIN_EMAIL` укажите почту, с которой входите на сайт, и перезапустите его. Ссылка «Тарифы» появится в шапке. Там же виден список счетов: если Робокасса списала деньги, а ключа нет, у счёта есть кнопка «Выдать ключ». Result URL в кабинете Робокассы: `https://ваш-домен/api/robokassa/result`. Если у панели самоподписанный сертификат, добавьте `XUI_INSECURE_TLS=1`.

В кабинете Робокассы: Result URL `https://ваш-домен/api/robokassa/result`, Success URL `https://ваш-домен/pay/success`, Fail URL `https://ваш-домен/pay/fail`.

Тарифы: 30 дней за 249 ₽, 90 дней за 599 ₽, 180 дней за 999 ₽, трафик без лимита.
